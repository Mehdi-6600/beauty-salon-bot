# هایپر سینا (Hyper Sina)

**حسابداری شخصیِ واقعی برای یک فروشگاه ایرانی** — فارسی، راست‌به‌چپ، موبایل‌اول، با در نظر گرفتن تورم و نرخ دلار.

هایپر سینا یک «داشبورد تزئینی» نیست: هر عددی که می‌بینید از یک پایگاه‌دادهٔ واقعی خوانده می‌شود و با قوانین حسابداری محاسبه می‌گردد. پول‌ها به **ریالِ صحیح (integer)** ذخیره می‌شوند تا خطای اعشار از بین برود، و همهٔ ضرب‌وتقسیم‌ها با `BigInt` انجام می‌شود.

> English: Hyper Sina is a Persian-first (RTL) personal accountant for an Iranian retail shop — sales, purchases with weighted-average inventory, ten expense categories, cash/bank accounts, receivables/payables, owner capital and loans, manual USD-rate history, user-entered inflation assumptions, real-vs-nominal profit analysis, monthly/yearly reports that can be *closed* into immutable snapshots, CSV/JSON export and role-based authentication. Zero npm dependencies, SQLite persistence, deployable to Vercel or any Node 22.5+ host.

---

## شروع سریع

```bash
node --version        # باید ۲۲٫۵ یا بالاتر باشد (به node:sqlite نیاز دارد)
npm start             # http://localhost:3000
```

```bash
npm run dev           # با --watch (توسعه)
npm run lint          # بررسی‌های ایستای خودِ پروژه (بدون وابستگی)
npm test              # آزمون‌ها: پول، تقویم جلالی، دیتابیس، موتور حسابداری، HTTP
npm run check         # lint + test
npm run build         # ساخت dist/ + manifest با هش sha256 برای هر فایل
```

هیچ `npm install` لازم نیست؛ پروژه عمداً **بدون وابستگی** نوشته شده است.

بارِ اول که برنامه را باز می‌کنید، از شما خواسته می‌شود یک حساب **مالک** بسازید. هیچ دادهٔ نمونه‌ای (demo/seed) در برنامه وجود ندارد و ساخته هم نمی‌شود — تا خودتان ثبت نکنید، چیزی نشان داده نمی‌شود.

## حسابداری — همان‌چه که سرور محاسبه می‌کند

```text
فروش خالص      = فروش کل − تخفیف‌ها − مرجوعی‌ها
بهای تمام‌شده  = مقدار فروش‌رفته × میانگین وزنیِ هزینهٔ موجودی (نه خریدِ آخر!)
سود ناخالص     = فروش خالص − بهای تمام‌شده
سود عملیاتی    = سود ناخالص − (هزینه‌های عملیاتی + تعدیلات کاهندهٔ موجودی)
سود خالص       = سود عملیاتی − بهرهٔ وام و سایر بارهای مالی
```

* **آورده/برداشت مالک درآمد یا هزینه نیست** و **اصل وام هزینه نیست**؛ فقط بهرهٔ وام در سود خالص می‌نشیند.
* خریدی که هنوز فروش نرفته، هزینه نیست — به موجودی می‌رود.
* وصول مطالبات، نقدینگی را زیاد می‌کند نه فروش را.
* حرکت موجودی همیشه بسته می‌شود: `موجودی اول + خرید + تعدیلات − بهای تمام‌شده = موجودی پایان` و برنامه این را به‌صورت `residual_rial` (باید صفر باشد) منتشر می‌کند؛ آزمون‌ها صفر بودنش را الزام می‌کنند.
* توضیح کامل‌تر و مثال‌های عددی: [`docs/ACCOUNTING-MODEL.md`](docs/ACCOUNTING-MODEL.md)

## دلار و تورم

* نرخ دلار **هیچ‌وقت** از اینترنت گرفته یا حدس زده نمی‌شود. هر رکورد یک تاریخ دارد؛ اگر «امروز» را اصلاح کنید، دیروز تغییر نمی‌کند.
* نرخ مبنای هر گزارش = آخرین رکوردِ تا پایان آن دوره — یا رکوردی که خودتان برای آن دوره انتخاب کرده‌اید (انتخاب، ویرایش تاریخچه نیست). منبع عدد (شناسهٔ رکورد و تاریخ) در نسخهٔ بسته‌شده ذخیره می‌شود.
* «میانگین ماه» یعنی میانگینِ ثبت‌های خودتان، با ذکر تعداد رکوردها — نه نرخ رسمی بازار.
* تورم هم فقط فرضِ واردشده توسط شماست. اگر ماهی ثبت نشده باشد عددی ساخته نمی‌شود؛ برنامه `available: false` و لیست ماه‌های جاافتاده را نشان می‌دهد.
* درصد تغییر نرخ دلار و درصد تورم دو شاخص جدا هستند و هرگز به‌جای هم استفاده نمی‌شوند.

## گزارش‌های بسته‌شده (Snapshot)

«بستن ماه» یک نسخهٔ ثابت می‌سازد شامل: جمع‌بندی محاسبه‌شده، نرخ دلار مبنای دوره + شناسهٔ رکورد منبع، فرض تورم استفاده‌شده، زمان محاسبه، وضعیت و شمارهٔ نسخه.

* بعد از بستن، تغییر نرخ دلار یا اصلاح داده‌ها نسخهٔ بسته‌شده را **بازنویسی نمی‌کند**؛ به‌جایش در گزارش زنده و با هشدار «از زمان بستن، n رقم تغییر کرده» نشان داده می‌شود.
* بازمحاسبه فقط برای مالک است، **ذکر دلیل الزامی** است، نسخهٔ جدید (`version + 1`، `status = restated`) ساخته می‌شود و نسخهٔ قبلی همیشه قابل مشاهده می‌ماند؛ هر بار در `report_corrections` ثبت می‌شود.
* اگر دادهٔ لازم کامل نباشد (مثلاً کالایی بدون بهای تمام‌شده فروخته شده)، گزارش **نهایی** بسته نمی‌شود: سرور `409` با لیست کاستی‌ها برمی‌گرداند و فقط «ذخیره به‌عنوان پیش‌نویس (برآورد)» ممکن است.

## امنیت و پایداری داده

* احراز هویت با `scrypt`، کوکی `HttpOnly` + `SameSite=Strict`، محدودسازی تلاش ناموفق (۸ بار در ۱۰ دقیقه → ۴۲۹)، تغییر رمز = خروج همهٔ دستگاه‌ها.
* نقش‌ها (مالک > کارمند > فقط‌خواندنی) در **سرور** بررسی می‌شوند؛ منوی مرورگر فقط ظاهر را عوض می‌کند.
* هر درخواست تغییردهنده باید توکن CSRF را در هدر `x-csrf-token` بیاورد.
* اعتبارسنجی سمت سرور: مبلغ باید به ریالِ صحیح یا تومانِ دقیق باشد (نه هر دو همزمان)، تاریخ آینده مجاز نیست، تخفیف بیشتر از مبلغ ردیف مجاز نیست، مرجوعی بیشتر از فروش مجاز نیست، کسر موجودی زیر صفر مجاز نیست.
* **Idempotency**: هر ارسال یک `dedupe_key` یکتا دارد؛ دوباره‌زدن دکمه یا تکرار شبکه `409` می‌گیرد و دو بار حساب نمی‌شود.
* ویرایش/حذف رکوردهای مالی بدون `reason` انجام نمی‌شود و همه در `audit_log` می‌نشینند.
* خروجی JSON (پشتیبان کامل، بدون هش رمزها) و CSV (با BOM تا Excel فارسی را خراب نکند). پیش از «پاک‌سازی کامل» همیشه پشتیبان خودکار نوشته می‌شود و عبارت «پاک کن» باید تایپ شود.
* مایگریشن‌ها شماره‌دار و **checksum**دار هستند؛ ویرایش یک مایگریشنِ اجراشده با خطا متوقف می‌شود و هیچ مایگریشنی `DROP TABLE` ندارد.

## استقرار

`vercel.json` + `api/index.js` آمادهٔ Vercel است؛ `docs/DEPLOY.md` مراحل، محدودیت دیسک سرورلس (فایل SQLite در آنجا خواندنی است) و گزینه‌های دیسک پایدار را توضیح می‌دهد. **برای استفادهٔ جدی، هایپر سینا را روی یک ماشین با دیسک نوشتنی (Node + SQLite) یا با `HYPER_SINA_DB` روی حجم متصل‌شده اجرا کنید.**

## محدودیت‌های شناخته‌شده

* Vercel Serverless دیسک نوشتنی پایدار ندارد؛ روی آن داده می‌تواند بین دو فراخوانی از بین برود. راه‌حل‌ها در `docs/DEPLOY.md`.
* مالیات بر ارزش افزوده، چک/سفته، انبار چندگانه، بارکدخوان و صورتحساب رسمی در این نسخه پیاده نشده‌اند.
* ساخت حساب کاربری فقط در راه‌اندازی اولیه آزاد است (حساب اول = مالک). افزودن کاربر بعدی از طریق دیتابیس/اسکریپت انجام می‌شود، نه رابط کاربری.
* خریدها «ساعت» ندارند؛ یک خریدِ همانِ روزِ فروش، در میانگین وزنیِ همان روز لحاظ می‌شود (قاعدهٔ مستند شده در `docs/ACCOUNTING-MODEL.md`).
